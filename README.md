# GQL - CV Management GraphQL API (with Prisma)

## Description

This project implements a GraphQL API for managing Curricula Vitae (CVs). It allows users to perform CRUD (Create, Read, Update, Delete) operations on CVs, associating them with users and skills. The API uses **Prisma** for data modeling and access, connecting to a **SQLite database** for persistent storage. It also supports real-time updates via GraphQL subscriptions.

## Features

*   **GraphQL API:** Provides a standard GraphQL interface for interacting with CV data.
*   **CV Management:**
    *   Create new CVs with name, age, job, associated user, and skills.
    *   Retrieve a list of all CVs or a specific CV by its ID.
    *   Update existing CVs.
    *   Delete CVs.
*   **Relational Data:** Manages relationships between CVs, Users, and Skills using Prisma's relation features.
*   **Persistent Storage:** Uses Prisma ORM to interact with a SQLite database (defined in `prisma/schema.prisma`).
*   **Real-time Updates:** Uses GraphQL subscriptions ([`graphql-yoga`](cci:7://file:///c:/Users/faleh/OneDrive/Documents/tp-nest/graphql/TpGraphql/src/index.ts:0:0-0:0) with `pubSub`) to notify clients about CV additions, updates, and deletions.

## Technology Stack

*   **Runtime:** Node.js
*   **Language:** TypeScript
*   **GraphQL Server:** `graphql-yoga`
*   **GraphQL Implementation:** `graphql`
*   **Database ORM:** Prisma
*   **Database Client:** `@prisma/client`
*   **Database:** SQLite (by default, configured in `prisma/schema.prisma`)
*   **Build/Dev Tool:** `@swc-node/register` for fast TypeScript execution

## Implementation Highlights

### Prisma Schema (`prisma/schema.prisma`)

Defines the database models (`User`, `Skill`, `Cv`) and their relationships, mirroring the GraphQL types. Configures the database connection (SQLite by default).

```prisma
// Example Cv model in prisma/schema.prisma
model Cv {
  id     String  @id @default(uuid())
  name   String
  age    Int
  job    String
  userId String
  user   User    @relation(fields: [userId], references: [id], onDelete: Cascade)
  skills Skill[] @relation("CvSkills") // Many-to-many

  @@index([userId])
}
```

### Resolvers (`src/resolvers.ts`)

Resolvers now use the **Prisma Client** instance (injected via the GraphQL context) to interact with the database.

*   **Data Fetching:** Queries like `getAllCvs` and `getCvById` use `prisma.cv.findMany()` and `prisma.cv.findUnique()`. The `include` option is used to eagerly load related `user` and `skills` data efficiently.
*   **Data Modification:** Mutations (`addCv`, `updateCv`, `deleteCv`) use `prisma.cv.create()`, `prisma.cv.update()`, and `prisma.cv.delete()`. Prisma handles database constraints and relation management (e.g., using `connect` or `set` for relations).
*   **Relationships:** Most relationship fetching is handled automatically by Prisma's `include`. Explicit type resolvers for `Cv.user` and `Cv.skills` are generally no longer needed unless custom logic is required.
*   **Subscriptions:** Mutations still publish events using `pubSub`. Subscription resolvers remain unchanged.

```typescript
// Example: getAllCvs Resolver using Prisma
getAllCvs: async (_: any, __: any, { prisma }: Context) => {
  return await prisma.cv.findMany({
    include: { // Include related user and skills
      user: true,
      skills: true,
    },
  });
},

// Example: addCv Mutation using Prisma (simplified)
addCv: async (_: any, { input }: any, { prisma, pubSub }: Context) => {
  // ... validation ...
  const newCv = await prisma.cv.create({
    data: {
      name: input.name,
      // ... other fields
      userId: input.user_id, // Connect relation
      skills: {
        connect: input.skill_ids.map((skillId: string) => ({ id: skillId })), // Connect many-to-many
      },
    },
    include: { user: true, skills: true } // Include relations in result
  });
  pubSub.publish("cvAdded", { cvAdded: newCv });
  return newCv;
},
```

## Prisma and GraphQL Synergy

This project leverages both Prisma and GraphQL, which work together effectively to create a robust and type-safe API:

*   **Prisma (Data Layer):** Acts as the Object-Relational Mapper (ORM). It connects directly to the database (SQLite in this case), manages the database schema (via `prisma/schema.prisma`), handles migrations, and provides a type-safe database client (`@prisma/client`) for querying and manipulating data. Prisma ensures that your interactions with the database are consistent with your defined data models.

*   **GraphQL (API Layer):** Defines the API contract through its schema (`src/schema.graphql`). It specifies the types, queries, mutations, and subscriptions available to clients. GraphQL allows clients to request exactly the data they need, preventing over-fetching.

**How they work together:**

1.  **Resolvers as the Bridge:** GraphQL resolvers (in `src/resolvers.ts`) are the crucial link. When a GraphQL operation (like `getCvById`) is received, the corresponding resolver function is executed. This resolver then uses the **Prisma Client** (passed via the context) to fetch or modify data in the database.
2.  **Solving the N+1 Problem:** A common issue in GraphQL is the "N+1 problem," where resolving nested fields might lead to numerous database queries (one for the parent, then N queries for N children). Prisma helps mitigate this significantly through its `include` and `select` options. By using `include: { user: true, skills: true }` in our resolvers, we tell Prisma to fetch the `Cv` along with its related `user` and `skills` in a more optimized way (often reducing it to a few queries instead of N+1).
3.  **Enhanced Type Safety:** This is a major benefit:
    *   **GraphQL Schema Types:** Your `schema.graphql` defines the types expected by the API clients.
    *   **Prisma Client Types:** Prisma generates a fully typed client based on your `schema.prisma`. When you use `prisma.cv.findMany(...)` in a resolver, the return type is precisely known (e.g., `Promise<(Cv & { user: User; skills: Skill[] })[] | null>`).
    *   **End-to-End Typing:** This combination provides strong type checking from the database interaction within the resolver all the way to the data returned by the GraphQL API. It catches potential type mismatches during development (e.g., trying to return a number where a string is expected by the GraphQL schema, or accessing a database field that doesn't exist) rather than at runtime. This significantly reduces bugs and improves maintainability.

In essence, Prisma handles the "how" of data access and persistence with type safety, while GraphQL defines "what" data is available and how clients can interact with it.

## Running the Project

1.  **Install dependencies:**
    ```bash
    npm install
    ```
2.  **Set up Database:**
    *   Ensure your `.env` file has the correct `DATABASE_URL` (defaults to `file:./dev.db` for SQLite).
    *   Run the Prisma migration to create the database schema:
        ```bash
        npx prisma migrate dev --name init # Or a more descriptive name if not the first migration
        ```
    *   (Optional, usually run automatically by `migrate dev` or install hooks) Generate Prisma Client:
        ```bash
        npx prisma generate
        ```
3.  **Run the development server:**
    ```bash
    npm run dev
    ```
    The server will start on `http://localhost:4000/graphql`. You can access the GraphQL Playground in your browser at this address to interact with the API. The API will now persist data in the `prisma/dev.db` SQLite file.
